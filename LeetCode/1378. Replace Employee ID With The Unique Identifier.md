# 1378. Replace Employee ID With The Unique Identifier

**Problem Name:** Replace Employee ID With The Unique Identifier
**Difficulty:** Easy

---

## Question

Given two tables:

* `Employees` contains employee names and IDs.
* `EmployeeUNI` contains unique IDs for some employees.

Return the `unique_id` and employee `name`.

If an employee does not have a unique ID, return `NULL`.

---

## My Solution

```sql
SELECT eu.unique_id, e.name
FROM Employees e
LEFT JOIN EmployeeUNI eu
ON e.id = eu.id;
```

---

## Approach

We use a `LEFT JOIN` because we need **every employee** from the `Employees` table.

```sql
LEFT JOIN EmployeeUNI eu
ON e.id = eu.id
```

The tables are matched using the employee `id`.

If a matching row exists in `EmployeeUNI`, we get its `unique_id`.

If no matching row exists, `unique_id` automatically becomes `NULL`.

---

## Example

For Alice:

```text
Employees:
id = 1
name = Alice
```

There is no `id = 1` in `EmployeeUNI`.

Therefore:

```text
unique_id = NULL
name = Alice
```

For Meir:

```text
Employees:
id = 11
name = Meir
```

`EmployeeUNI` contains:

```text
id = 11
unique_id = 2
```

Therefore:

```text
unique_id = 2
name = Meir
```

---

## Why `LEFT JOIN`?

If we used an `INNER JOIN`, employees without a matching unique ID would be removed.

But the problem requires Alice and Bob to appear with `NULL`.

Therefore, `LEFT JOIN` is required.

---

## Key Takeaway

Use:

```sql
LEFT JOIN
```

when you want **all rows from the left table**, even when there is no matching row in the right table.

```text
Employees
   ↓
LEFT JOIN
   ↓
EmployeeUNI
   ↓
No match → NULL
```

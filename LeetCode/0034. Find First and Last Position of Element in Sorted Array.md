# 0034. Find First and Last Position of Element in Sorted Array

**Problem Name:** Find First and Last Position of Element in Sorted Array  
**Difficulty:** Medium

---

## Question

Given a sorted array `nums` and a `target`, find the starting and ending position of the target.

If the target does not exist, return:

```text
[-1, -1]
```

The solution must use `O(log n)` runtime complexity.

---

## My Solution

```cpp
class Solution {
public:
    int findFirst(vector<int>& nums, int target) {

        int left = 0;
        int right = nums.size() - 1;
        int ans = -1;

        while (left <= right) {

            int mid = left + (right - left) / 2;

            if (nums[mid] == target) {
                ans = mid;
                right = mid - 1;
            }
            else if (nums[mid] < target) {
                left = mid + 1;
            }
            else {
                right = mid - 1;
            }
        }

        return ans;
    }

    int findLast(vector<int>& nums, int target) {

        int left = 0;
        int right = nums.size() - 1;
        int ans = -1;

        while (left <= right) {

            int mid = left + (right - left) / 2;

            if (nums[mid] == target) {
                ans = mid;
                left = mid + 1;
            }
            else if (nums[mid] < target) {
                left = mid + 1;
            }
            else {
                right = mid - 1;
            }
        }

        return ans;
    }

    vector<int> searchRange(vector<int>& nums, int target) {

        int first = findFirst(nums, target);
        int last = findLast(nums, target);

        return {first, last};
    }
};
```

---

## Complexity

| Metric | Value |
|--------|-------|
| **Time Complexity** | `O(log n)` |
| **Space Complexity** | `O(1)` |

---

## What I Learned

This problem helped me understand how to modify **Binary Search** to find the first and last occurrence of a value.

For the first position, when I find the target, I continue searching on the **left side** because there might be another target before it.

For the last position, when I find the target, I continue searching on the **right side** because there might be another target after it.

---

## Personal Notes

Initially, I thought about simply traversing the entire array and storing the first and last occurrence. That solution is easier, but it takes `O(n)` time.

Since the array is sorted, Binary Search allows me to find both positions in `O(log n)`. This problem helped me understand that Binary Search can be modified to find the **first or last occurrence**, not just whether an element exists.

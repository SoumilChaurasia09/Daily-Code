# 91. Decode Ways

**Problem Name:** Decode Ways
**Difficulty:** Medium

---

## Question

A string of digits represents letters using this mapping:

```text
1  -> A
2  -> B
...
25 -> Y
26 -> Z
```

A digit can be decoded individually, or two consecutive digits can sometimes be decoded together.

Find the total number of valid ways to decode the entire string.

A number with a leading zero, such as `06`, is invalid.

---

## My Solution

```cpp
class Solution {
public:
    int numDecodings(string s) {
        int n = s.size();

        if (s[0] == '0') {
            return 0;
        }

        vector<int> dp(n + 1, 0);
        dp[0] = 1;
        dp[1] = 1;

        for (int i = 2; i <= n; i++) {
            if (s[i - 1] != '0') {
                dp[i] += dp[i - 1];
            }

            int twoDigit = (s[i - 2] - '0') * 10 + (s[i - 1] - '0');

            if (twoDigit >= 10 && twoDigit <= 26) {
                dp[i] += dp[i - 2];
            }
        }

        return dp[n];
    }
};
```

---

## Approach

This problem can be solved using **Dynamic Programming**.

Let:

```text
dp[i] = number of ways to decode the first i characters
```

We check two possibilities for every position.

### 1. Decode one digit

If the current digit is not `0`, it can be decoded by itself.

For example:

```text
1 → A
6 → F
9 → I
```

So:

```cpp
if (s[i - 1] != '0') {
    dp[i] += dp[i - 1];
}
```

We use `dp[i - 1]` because the current digit is decoded separately.

---

### 2. Decode two digits

We take the previous two digits:

```cpp
int twoDigit = (s[i - 2] - '0') * 10 + (s[i - 1] - '0');
```

The two-digit number is valid only when it is between `10` and `26`.

```cpp
if (twoDigit >= 10 && twoDigit <= 26) {
    dp[i] += dp[i - 2];
}
```

For example:

```text
12 → L
26 → Z
```

Both are valid.

But:

```text
27
35
```

cannot represent a single letter.

---

### Why `dp[i - 2]`?

If two digits are decoded together, we have already decoded everything before those two digits.

Therefore:

```text
dp[i] += dp[i - 2]
```

---

### Handling zero

A standalone `0` is invalid because there is no mapping:

```text
0 → ?
```

However, `0` can be used as part of:

```text
10
20
```

For example:

```text
"10"
```

has exactly one decoding:

```text
10 → J
```

But:

```text
"06"
```

is invalid because `06` is not a valid code.

The conditions in the solution correctly handle these cases.

---

## Example

Consider:

```text
s = "226"
```

Possible decodings are:

```text
2 2 6
2 26
22 6
```

So the answer is:

```text
3
```

The DP table becomes:

```text
dp[0] = 1
dp[1] = 1
dp[2] = 2
dp[3] = 3
```

Therefore:

```text
dp[3] = 3
```

---

### Example with zero

Consider:

```text
s = "11106"
```

Valid decodings include:

```text
1 1 10 6
11 10 6
```

The grouping:

```text
1 11 06
```

is invalid because `06` is not a valid code.

Therefore, the answer is:

```text
2
```

---

## Complexity

**Time Complexity:** `O(n)`

We process every character once.

**Space Complexity:** `O(n)`

The `dp` array stores the number of decoding ways for every prefix of the string.

---

## Key Takeaway

At every position, there are at most two choices:

```text
1 digit → valid if it is not 0
2 digits → valid if the number is between 10 and 26
```

The main DP formula is:

```text
dp[i] = dp[i - 1] + dp[i - 2]
```

when both one-digit and two-digit decodings are valid.

Dynamic programming works because the number of ways to decode a prefix can be reused to calculate the number of ways for larger prefixes.

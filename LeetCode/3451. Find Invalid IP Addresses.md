# 3451. Find Invalid IP Addresses

**Problem Name:** Find Invalid IP Addresses
**Difficulty:** Hard

---

## Question

We need to find IP addresses that are not valid IPv4 addresses.

An IP address is invalid if:

* It has fewer or more than 4 octets.
* Any octet is greater than `255`.
* Any octet contains leading zeros.

For every invalid IP address, count how many times it appears in the `logs` table.

Finally, sort by:

1. `invalid_count` descending
2. `ip` descending

---

## My Solution

```sql
SELECT
    ip,
    COUNT(*) AS invalid_count
FROM logs
WHERE ip NOT REGEXP '^((0|[1-9][0-9]?|1[0-9]{2}|2[0-4][0-9]|25[0-5])\\.){3}(0|[1-9][0-9]?|1[0-9]{2}|2[0-4][0-9]|25[0-5])$'
GROUP BY ip
ORDER BY invalid_count DESC, ip DESC;
```

---

## Approach

### 1. Use REGEXP to check a valid IPv4 format

The important part is:

```sql
REGEXP '^((...)\.){3}(... )$'
```

A valid IPv4 address must contain exactly **4 octets** separated by `.`.

For example:

```text
192.168.1.1
```

has:

```text
192 | 168 | 1 | 1
```

The pattern checks three octets followed by `.` and then checks the final octet.

---

### 2. Check the valid range of each octet

The octet pattern is:

```sql
0|[1-9][0-9]?|1[0-9]{2}|2[0-4][0-9]|25[0-5]
```

It allows:

```text
0
1 - 99
100 - 199
200 - 249
250 - 255
```

Therefore, values greater than `255` are rejected.

For example:

```text
256
```

does not match the pattern, so the IP is invalid.

---

### 3. Prevent leading zeros

This part:

```sql
[1-9][0-9]?
```

requires a multi-digit number to start with a digit from `1` to `9`.

Therefore:

```text
01
001
09
```

are not accepted.

But:

```text
1
10
100
```

are accepted.

---

### 4. Check exactly four octets

The pattern:

```sql
((octet)\.){3}(octet)
```

requires exactly three dots and four octets.

Therefore:

```text
192.168.1
```

is invalid because it has only three octets.

Similarly:

```text
192.168.1.1.5
```

is invalid because it has five octets.

---

### 5. NOT REGEXP

We want the **invalid** IP addresses.

Therefore, instead of:

```sql
ip REGEXP 'valid_pattern'
```

we use:

```sql
ip NOT REGEXP 'valid_pattern'
```

This keeps only invalid IP addresses.

---

### 6. COUNT invalid occurrences

The same invalid IP can appear multiple times.

For example:

```text
256.1.2.3
256.1.2.3
```

should produce:

```text
256.1.2.3 | 2
```

So we use:

```sql
COUNT(*)
```

and group by:

```sql
GROUP BY ip
```

---

### 7. ORDER BY

The problem requires descending order by `invalid_count` and then `ip`.

```sql
ORDER BY invalid_count DESC, ip DESC
```

The first sorting criterion is the number of invalid occurrences.

If two IPs have the same count, their IP strings are sorted in descending order.

---

## Example

Consider:

```text
256.1.2.3
```

The first octet is:

```text
256
```

Since:

```text
256 > 255
```

the IP is invalid.

If it appears twice:

```text
256.1.2.3
256.1.2.3
```

then:

```sql
COUNT(*)
```

returns:

```text
2
```

For:

```text
192.168.001.1
```

the octet:

```text
001
```

has leading zeros, so the IP is invalid.

For:

```text
192.168.1
```

there are only three octets, so the IP is invalid.

---

## Complexity

**Time Complexity:** `O(n × L)`

Where `n` is the number of rows and `L` is the length of the IP string. The regular expression checks each IP.

**Space Complexity:** `O(k)`

Where `k` is the number of distinct IP addresses stored during grouping.

---

## Key Takeaway

For string-validation SQL problems, `REGEXP` can be used to describe the valid format.

A useful pattern here is:

```sql
WHERE ip NOT REGEXP 'valid_IP_pattern'
```

This means:

> Keep only values that do **not** match the valid IPv4 pattern.

Then use:

```sql
GROUP BY ip
COUNT(*)
```

to count how many times each invalid IP occurs.

# 1251. Average Selling Price

**Problem Name:** Average Selling Price
**Difficulty:** Easy

---

## My Solution

```sql
SELECT 
    p.product_id,
    ROUND(
        COALESCE(SUM(p.price * u.units) / SUM(u.units), 0),
        2
    ) AS average_price
FROM Prices p
LEFT JOIN UnitsSold u
    ON p.product_id = u.product_id
    AND u.purchase_date BETWEEN p.start_date AND p.end_date
GROUP BY p.product_id;
```

---

## Why the Previous Query Failed

The previous solution used:

```sql
JOIN UnitsSold u
```

This is an `INNER JOIN`.

If a product has **no sales**, there is no matching row in `UnitsSold`, so that product completely disappears from the result.

In the screenshot:

```text
Prices:
1 → 10
2 → 20

UnitsSold:
no rows
```

The expected result is:

```text
1 → 0
2 → 0
```

But an `INNER JOIN` returns no rows.

---

## Fix 1: Use `LEFT JOIN`

We start with every product from `Prices`:

```sql
FROM Prices p
LEFT JOIN UnitsSold u
```

Now products without sales are still present.

Their `UnitsSold` values are `NULL`.

---

## Fix 2: Convert NULL to 0

For products with no sales:

```sql
SUM(u.units)
```

is `NULL`.

So we use:

```sql
COALESCE(..., 0)
```

This converts the missing average into `0`.

---

## Complete Logic

```text
Prices
   ↓
LEFT JOIN UnitsSold
   ↓
Match purchase date with price period
   ↓
Calculate price × units
   ↓
SUM(revenue) / SUM(units)
   ↓
COALESCE(..., 0)
   ↓
ROUND(..., 2)
```

---

## Key Takeaway

When the problem says:

> If a product does not have any sold units, its average selling price is 0.

Use:

```sql
LEFT JOIN
```

instead of:

```sql
INNER JOIN
```

and handle missing values with:

```sql
COALESCE(..., 0)
```

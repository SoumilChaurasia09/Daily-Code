# 262. Trips and Users

**Problem Name:** Trips and Users
**Difficulty:** Hard

---

## Question

Find the cancellation rate for each day from `2013-10-01` to `2013-10-03`.

A trip should be included only when:

* The client is not banned.
* The driver is not banned.

A trip is considered cancelled when its status is either:

* `cancelled_by_client`
* `cancelled_by_driver`

The cancellation rate is:

```text
cancelled trips / total valid trips
```

The result must be rounded to 2 decimal places.

---

## My Solution

```sql
SELECT
    t.request_at AS Day,
    ROUND(
        AVG(
            CASE
                WHEN t.status <> 'completed' THEN 1
                ELSE 0
            END
        ),
        2
    ) AS `Cancellation Rate`
FROM Trips t
JOIN Users c
    ON t.client_id = c.users_id
JOIN Users d
    ON t.driver_id = d.users_id
WHERE t.request_at BETWEEN '2013-10-01' AND '2013-10-03'
  AND c.banned = 'No'
  AND d.banned = 'No'
GROUP BY t.request_at;
```

---

## Approach

### 1. Join the `Trips` table with `Users`

We need to check whether **both the client and driver are unbanned**.

Therefore, we join the `Users` table twice:

```sql
JOIN Users c
    ON t.client_id = c.users_id
```

This gets the client information.

```sql
JOIN Users d
    ON t.driver_id = d.users_id
```

This gets the driver information.

We use different aliases (`c` and `d`) because we are using the same `Users` table for two different users.

---

### 2. Filter banned users

```sql
WHERE c.banned = 'No'
  AND d.banned = 'No'
```

This ensures that both the client and driver are unbanned.

A trip is excluded if either the client or driver is banned.

---

### 3. Filter the required dates

```sql
WHERE t.request_at BETWEEN '2013-10-01' AND '2013-10-03'
```

Only trips from the three required dates are considered.

---

### 4. Identify cancelled trips using CASE

```sql
CASE
    WHEN t.status <> 'completed' THEN 1
    ELSE 0
END
```

Every valid trip becomes:

```text
completed             → 0
cancelled_by_client   → 1
cancelled_by_driver   → 1
```

---

### 5. Calculate cancellation rate using AVG

```sql
AVG(
    CASE
        WHEN t.status <> 'completed' THEN 1
        ELSE 0
    END
)
```

Because cancelled trips are represented by `1` and completed trips by `0`, their average gives the cancellation rate.

For example:

```text
1 + 0 + 0
---------
    3

= 0.33
```

---

### 6. Round the result

```sql
ROUND(..., 2)
```

This rounds the cancellation rate to two decimal places.

---

### 7. GROUP BY each day

```sql
GROUP BY t.request_at
```

This calculates a separate cancellation rate for each date.

---

## Example

For `2013-10-01`, there are 4 trips.

The trip made by banned client `2` is excluded.

The remaining valid trips are:

```text
completed
completed
cancelled_by_client
```

Convert them using `CASE`:

```text
0
0
1
```

Therefore:

```text
(0 + 0 + 1) / 3
= 0.33
```

So:

```text
2013-10-01 | 0.33
```

For `2013-10-03`, the valid trips are:

```text
completed
cancelled_by_driver
```

Therefore:

```text
(0 + 1) / 2
= 0.50
```

---

## Complexity

**Time Complexity:** `O(n)`

The query processes the trips and performs joins and grouping based on the number of rows.

**Space Complexity:** `O(n)`

The database may use additional space for joins and grouping.

---

## Key Takeaway

When the same table represents different roles, such as client and driver, join it multiple times using different aliases:

```sql
JOIN Users c
JOIN Users d
```

For a percentage/rate based on a condition, a useful pattern is:

```sql
AVG(
    CASE
        WHEN condition THEN 1
        ELSE 0
    END
)
```

Here, `1` represents a cancelled trip and `0` represents a completed trip, so the average directly gives the cancellation rate.
